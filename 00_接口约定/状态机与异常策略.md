# 状态机与异常策略

> ## ⚠️ 2026-10-27 现状声明（先读这段）
>
> **当前固件不是状态机**。`AutoMeasureSort.ino`（10.23 源程序）是**单文件顺序流程**：
> `发 image → 等 400 ms → 收帧校验 → 入桶计数 → HMI 上报 → 6 档分选动作 → 收尾 1000 ms → 循环`。
>
> - 本文 **§1 / §2** 是**阶段 1 的目标设计**，代码里**一项都没有实现**；
> - **§3 / §4** 已按 2026-10-27 实测**重写为"当前实现"**；
> - **§5 / §6** 是给阶段 1 的落地清单，**全部未完成**，且部分条目已因接口变更（`Re,` 帧、442 类）需重写；
> - 依据：决策记录 A4（漏检重试 / 掉线停机 / 需急停）——**这三项目前都没有**。
>
> 若要用本文判断"程序现在在做什么"，只看 §3 / §4。

## 1 目标状态机（阶段 1 完成后，**当前未实现**）

```
上电 → BOOT（等 K230 最多 10 s）
        ↓ 超时/失败
     PROBE（发 image，收到任意合法帧 = 在线）→ ERROR
        ↓ 在线
       RUN（发 image；收 NONE=漏检计数，收 id=识别到）
        ↓
     DETECTED → SORT → RELEASE → DELAY → RESET → RUN
                    ↓ 超时看门狗        ↓
                 ERROR ←──────────────┘
任意状态 ──`e`/物理急停──→ ESTOP ──`r`──→ BOOT
ERROR   ──`r`──────────→ BOOT
```

| 状态 | 进入动作 | 退出条件 | 必须打的日志 |
|---|---|---|---|
| BOOT | 停三级带，电机使能 | 10 s 或收到 PROBE 应答 | `BOOT` |
| PROBE | 发一次 `image` | 收到任意合法帧 → RUN；10 s 无任何字节 → ERROR | `PROBE online/offline` |
| RUN | 发 `image`，启动三级带 | 收到 id → DETECTED；超时 → 计数 | `TX image`、`RX ...` |
| DETECTED | 停三级带，解析 id → 颜色/形状，随机选位 | 立即 | `检测到目标: 标签=37 置信度=87%` |
| SORT | 分选电机到 `pos` | 到位 或 超时 → ERROR | `分选电机 -> 位置 n` |
| RELEASE | 开合电机到开位 | 到位 或 超时 → ERROR | `开合电机 打开` |
| DELAY | 计时 | ≥1000 ms | — |
| RESET | 关开合 + 分选复位 | 两轴到位 | `开合关闭 + 分选复位` |
| ERROR | 停三级带、电机保持使能、**不再发 image** | `r` | `OFFLINE` / `SORT_TIMEOUT` / `PROBE_FAIL` |
| ESTOP | 停三级带、记录、拒绝一切运动指令 | `r`（建议同时要求物理复位） | `ESTOP` |

> ⚠️ 该目标设计写于 2026-10-18，当时接口是 `37 0.87\n` + `NONE` + 403 类。
> 现在接口已改为 `Re,37,0.87` + 无 `NONE` + 442 类：**`PROBE` 的"任意合法帧"判据、`NONE` 漏检计数都需要按新接口重写**才能落地。

## 2 异常策略（A4 的落地规则，**当前未实现**）

| 情形 | 目标判据 | 目标动作 | 日志/埋点 |
|---|---|---|---|
| 空视野 / 低阈值 | 视觉不回包（新接口取消 `NONE`） | 本圈无动作，继续下一圈；计入"漏检" | `MISS` |
| 400 ms 内无回包 | 超时 | 重发 `image`；累计超时次数 | `TIMEOUT n` |
| 连续 N 次超时 | 待定（旧值 10 次） | → `ERROR`，停带、电机保持使能 | `OFFLINE` |
| 分选 / 开合卡住 | `SORT_TIMEOUT_MS` 看门狗 | → `ERROR` | `SORT_TIMEOUT` |
| 急停 | 串口 `e` 或物理按钮 | → `ESTOP`，停带 | `ESTOP` |
| 复位 | 串口 `r` | 清计数，回 `BOOT` | `RESET` |
| 满 6 桶 | 第 7 个新类别 | 应报警/停机；**当前是静默丢弃** | `FULL` |

## 3 当前实现（2026-10-27 实测，`AutoMeasureSort.ino`）

| 项 | 现状 | 证据 |
|---|---|---|
| 程序结构 | **单文件顺序流程**，`loop()` 内从头跑到底，无 `switch`/状态变量 | `AMS:354-469` |
| 状态集合 | **无**（不存在 `RUN/DETECTED/SORT/...`，也没有 `BOOT/PROBE/ERROR/ESTOP`） | 全文 |
| 停带机制 | **Timer3 1 ms 中断**采样 44/45；只认**下降沿**（高→低）；检测到后延迟 **500 ms** 才拉低 A1/A2 停带 | `AMS:99`、`AMS:101-122`、`AMS:343-348` |
| 停带变量 | `volatile bool stop1/stop2`（中断与主程序共享）；`applyConveyors()` 每圈统一输出，`Out3` 恒 HIGH | `AMS:43-44`、`AMS:82-86` |
| 触发 / 收帧 | 每圈发 1 次 `image` → `delay(400)` → `Serial2.readString()` + `trim()`；靠串口 idle 超时断帧 | `AMS:382-386` |
| 帧校验 | `checkK230Frame()`：`Re,<id>,<conf>`，id 0..441、conf 0..1；非法帧打 `[WARN]` 后丢弃 | `AMS:221-267`、`AMS:373-378`、`AMS:392-397` |
| 重试 / MISS | **无**：不重发、不计数 | 全文 |
| `NONE` 分支 | **无**，且 `NONE` 会被判非法帧 | `AMS:231`（必须以 `Re,` 开头） |
| 分选动作 | 6 个 `if (Category == n)` 块，各自 `runToNewPosition()`（阻塞）+ 固定延时；无回零动作 | `AMS:405-459` |
| 运动输出时机 | 只在分选块里调 `runToNewPosition()`；主循环**没有** `run()` 轮询 | `AMS:406-459` |
| 超时看门狗 | **无**：`runToNewPosition()` 阻塞，堵转即永久卡住 | 同上 |
| 急停 / 复位 | **无**：全文无 `Serial.read`，串口 `e`/`r` 无效 | 全文 |
| 桶管理 | 6 槽：先查旧码复用，再占新槽；**满 6 槽后静默丢弃** | `AMS:271-298` |
| diaglog | **未 include**，无 `d`/`c`，无 RESET 记录 | — |

## 5 合法迁移表（阶段 1 用；**当前不适用**）

当前程序没有状态，无法按表分析迁移。待阶段 1 状态机落地后再启用：

```
BOOT→PROBE  PROBE→RUN  PROBE→ERROR
RUN→DETECTED  RUN→ERROR
DETECTED→SORT  SORT→RELEASE  SORT→ERROR
RELEASE→DELAY  DELAY→RESET  RESET→RUN
*→ESTOP  ESTOP→BOOT  ERROR→BOOT
```

## 6 阶段 1 实现清单（**全部未完成**，已按新接口调整前提）

| # | 改动 | 通过判据 | 陷阱 |
|---|---|---|---|
| 0 | **先冻结 v0.4 接口**（`Re,` 帧、442 类、TJC 115200、`data0`/`p0..p5`） | 三人确认 + tag | 接口没冻结就动状态机 = 返工 |
| 1 | 加 `BOOT→PROBE→RUN` | 模拟模式打印 `BOOT→PROBE→RUN`；注入"K230 无响应"→ `ERROR` | `NONE` 已取消，PROBE 判据要改成"收到任意合法 `Re,` 帧" |
| 2 | 加 `ERROR / ESTOP` | 模拟 `e` → `ESTOP`、三级带全 false；`r` 能回 `BOOT` | 复位漏清计数器/帧缓冲 → 状态卡住 |
| 3 | 加漏检/超时计数（替代旧 `NONE` 计数） | 连续不回包 → 计数并报警 | 新接口没有 `NONE`，"漏检"只能靠"400 ms 内无回包"判定 |
| 4 | 加 `SIMULATION_MODE` 开关 | 不接硬件跑完整 5 循环，假 `id=37`，不驱动 IO | 全局搜 `digitalWrite` / `runToNewPosition` 防漏 |
| 5 | `SORT_TIMEOUT_MS` 看门狗 | 堵转 → 超时进 `ERROR` 并打日志 | `runToNewPosition()` 阻塞，要么换成 `run()` 轮询，要么用中断/超时库 |
| 6 | 无效帧日志与计数 | 半帧/乱码/超长 → 有日志 + 计数 | 现在只打一行 `[WARN]`，无计数 |
| 7 | 恢复 diaglog | 加 `MISS/TIMEOUT/OFFLINE` 事件；K230 id 扩 **16 位**；解除"5 循环停写" | 442 类里 id≥256 的 186 类会被 8 位字段截断 |
| 8 | 满桶策略 | 第 7 个新类别要有提示/停机，不能静默丢弃 | `codeToBucket()` 无满桶分支 |

## 7 移植整合版 ERROR/ESTOP 前的 6 条反面清单（照抄会踩坑，保留作参考）

| # | 整合版现状 | 后果 | 做法 |
|---|---|---|---|
| 1 | ERROR 里只 `conveyorStopAll`，**不停电机、无出口**（`GS:286-300`） | 一进 ERROR 只能断电 | 改为停带 + 电机保持使能 + `r` 可复位 |
| 2 | 串口命令只在 `SIMULATION_MODE` 下读（`GS:423`） | 真实模式无法急停/复位 | 命令通道独立于模拟开关 |
| 3 | 电机只在 SORT/RELEASE/RESET 三个状态 `run()`（`GS:249-284`） | 运动中被打断会停半路且不报警 | 保持每 loop `run()` 的结构 |
| 4 | 默认 `SIMULATION_MODE=1`（`config.h:25`） | 误烧整合版 → "电机/传送带/屏全不动"，极易误判硬件坏 | 归档时改 0 并在 README 顶部红字标注 |
| 5 | 仍带"6 盒标签映射 + 满则停机"（`GS:80-99`、`HALT_ON_SLOT_FULL=1`） | 真实 442 类场景下第 7 个不同标签必进 ERROR | 本轮是"满 6 槽静默丢弃"，要改就统一改，别只改调用点 |
| 6 | 测试版 `HALT` 无出口 + PROBE 3 s 超时（`T:379-382,460-469`） | 真机每次上电必然死锁 | 别把测试版当基线，只借它的状态名 |
