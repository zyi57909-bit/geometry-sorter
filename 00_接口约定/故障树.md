# 故障树（现象 → 模块 → 你先做 → 何时转交）

- 用法：**先按现象定位模块，再做"你先做的初步排查"；只有做完还不行才转交**，转交时带上"我已经排除了什么"
- 前置：三张分模块自检表见 §2；三张各自通过后再合体
- **2026-10-27 按 10.23 固件重写**：删掉 6 条与当前代码无关的旧条目（PROBE/六状态机/`t1/t2` 数字控件/`NONE`/diaglog 等），新增 6 条新机制相关条目

## 1 现象 → 模块 → 排查 → 转交

| # | 现象 | 最可能模块 | 你先做的初步排查 | 什么情况转交 |
|---|---|---|---|---|
| 1 | **上电后屏全黑 / 毫无反应** | HMI（波特率） | USB-TTL 直发 `t0.txt="hi"` + `FF FF FF`，**先试 115200**，再试 9600 | 两个都不动 → **转交 HMI** |
| 2 | **屏有字但名字不变** | 主控→HMI 链路 | 看 USB 串口有没有"桶号+数量"输出；有 → 是屏侧问题 | 串口有输出、屏不动 → 查 baud 是否 115200 / 共地 |
| 3 | **屏上中文乱码 / 方块** | HMI（字库编码） | 固件发的是**中文名**（如 `红球体`），改发英文试 | 英文正常、中文乱码 → 字库缺字，**转交 HMI** |
| 4 | **`data0` 表格永远不增行** | HMI（数据记录控件） | 用 USB-TTL 直发 `data0.insert("1^测试^1")` + `FF FF FF` | 直发也不动 → 控件指令名/列数不对，**转交 HMI** |
| 5 | **`p0..p5` 图片不显示或显示错物** | HMI（图片号） | 直发 `p0.pic=91` 看显示什么 | 显示的不是"红球体" → 图片号与类别码不是同一套编号，**转交 HMI** |
| 6 | **传送带完全不转** | 主控 / 硬件 | 万用表量 A1/A2/A3 电平；程序里手动置高测一次 | 引脚有电平但带不转 → 继电器/供电，**不是软件** |
| 7 | **带一直转、物体到了也不停** | 传感器 / 中断 | 手挡住 44/45，量电平是否由高变低；串口看有无动作 | 电平会变但仍不停 → 中断没开/引脚错；电平不变 → 传感器/接线（NPN 需外部或内部上拉，代码是 `INPUT_PULLUP`） |
| 8 | **停带位置偏（冲过头/停太早）** | 主控（停带延迟） | 改 `STOP_DELAY_MS`（`AMS:99`，当前 500 ms）实测对比 | 调到 0/200/800 仍不对 → 带速与工位距离不匹配，机械侧处理 |
| 9 | **重启后被同一物体立刻又停住** | 主控（边沿判定） | 确认代码仍是"只认高→低下降沿" | 若有人改回"低电平就停"，改回去（`AMS:106`、`AMS:115`） |
| 10 | **带一直转、永不识别** | K230→主控链路 | 看 USB 串口有没有 `[WARN] K230 帧格式不合法` | 有 `[WARN]` → 帧格式不对（前缀不是 `Re,`/多余逗号/标签非数字）→ **转交视觉** |
| 11 | **K230 第一次就不回** | 视觉 / 物理层 | 电脑串口助手 115200 发 `image` 给它 | 电脑发也不回 → **转交视觉**（脚本崩/没跑起来/波特率） |
| 12 | **前几件正常，某件之后 K230 永久不回** | 视觉（`color_four` 越界） | 重启 K230 是否恢复 | 是 → 几乎确定调色板越界（现在类别到 441，越界风险更大）→ **转交视觉** |
| 13 | **一件都没入桶，只刷 `[WARN]`** | 视觉（回包前缀） | 抓原始字节，看是不是 `Re,37,0.87` | 是 `37 0.87`（无 `Re,`）或中文名 → **转交视觉**改回包 |
| 14 | **颜色/形状显示全错但流程正常** | 视觉（类别表） | 对表：应为 442 类、`颜色=id%13`、`形状=id/13` | 条数/顺序不对 → **转交视觉**（这是静默失败，最危险） |
| 15 | **分选位置偏一格 / 偏半格** | 主控（原点/间距） | 手动逐位对盒；确认间距是 **325 步**（0/325/650/975/1300/1625） | 脉冲对但盒位错 → 原点假设 → 上电人工对位 |
| 16 | **开合角度不对 / 关不严** | 主控（参数） | 确认是 **开=0、关=850（桶 1、2）/750（桶 3~6）**，不是旧值 711/777 | 参数对仍不对 → 方向/堵转/机械卡滞 |
| 17 | **卡在某个分选位置不动、电机嗡嗡响** | 电机 / 驱动 / **无看门狗** | 断电手转看是否卡滞；看是否堵转 | `runToNewPosition()` **阻塞**且无超时 → 堵转就永久卡住，只能断电。属已知识缺陷，要改需阶段 1 加看门狗 |
| 18 | **同一件被分选两次** | 传感器 / 节拍 | 看是不是重启后同一物体还在挡光 | 下降沿已能防重复；若仍重复 → 物体被带子顶回去两次，机械问题 |
| 19 | **跑一会儿 Arduino 自动重启** | 电源 | 量 VCC 是否跌落；共地是否良好 | VCC 跌 → 电源容量/共地，**不是代码**。注意：diaglog 未启用，**看不到 RESET 记录** |
| 20 | **满 6 个桶后新物体消失** | 主控（满桶静默丢弃） | 数已占槽数是否 = 6 | 是 → 属当前实现（`AMS:271-298` 无满桶分支），不是故障；要提示需改代码 |
| 21 | **想按屏上按钮急停没反应** | HMI / 主控（未开发） | 查代码有无 `Serial1.read` | **固件完全不读 Serial1** → 属未开发，不是故障；本轮只能断电 |
| 22 | **串口发 `d` / `c` / `e` / `r` 都没反应** | 主控（未实现） | 查 `.ino` 有无 `Serial.read`、有无 `#include "diaglog.h"` | 都没有 → 属未实现（diaglog 未启用），不是故障 |
| 23 | **上电全不动（带/电机/屏都不动）** | 主控（烧错程序） | 看程序名；整合版 `GeometricSorting` 默认 `SIMULATION_MODE=1`，所有 IO 被短路 | 是整合版 → 重烧 AMS |

## 2 合体前的三张分模块自检表

### 2.1 主控单独测（不接 K230、不接屏）

| 检查项 | 怎么测 | 通过标准 |
|---|---|---|
| 程序跑起来 | USB 串口 115200 看输出 | 上电后 A1/A2/A3 三路都输出高（三级带转） |
| 停带 | 手/纸片挡住 44 号传感器 | 约 **0.5 s 后** A1 变低；移开后不会被同一物体重复触发 |
| 二级停带 | 挡住 45 号 | 约 0.5 s 后 A2 变低 |
| 分选轴 | 串口模拟发 `Re,0,0.9`（临时调试）或直接看分选动作 | X 走到位置 0，停 2 s |
| 开合轴 | 同上 | Y 走 0（开）→ 等 2 s → 走 850/750（关） |
| 桶计数 | 连发同一 id 3 次 | 串口打印 `1,数量1/2/3` 递增 |

> ⚠️ 不要再用"看 `BOOT→PROBE` 状态日志"验收 —— 当前程序没有状态机（见《状态机与异常策略》§3）。

### 2.2 K230 单独测（不接 Mega）

| 检查项 | 怎么测 | 通过标准 |
|---|---|---|
| 摄像头 | 接屏看画面 | 正常无花屏 |
| 模型 | 放一个几何体 | 屏上画出框 |
| 串口回包 | 电脑串口助手 115200 发 `image`（hex `69 6D 61 67 65`） | 收到 **`Re,37,0.87`** 这类帧（前缀必须是 `Re,`） |
| 类别范围 | 多次触发 | id 落在 **0..441** |
| 未识别 | 视野清空发 `image` | **可以不回**（新接口取消了 `NONE`）；若回了 `NONE`，主控会打 `[WARN]` 并丢弃 |
| 抗粘连 | 连发 10 次 `image` | 10 个回包；不要出现 `Re,Re,` 粘连 |
| 单帧耗时 | 10 次平均 | 得到 ms 值（决定 400 ms 是否够），写进参数表 |

### 2.3 HMI 单独测（不接 Mega，USB-TTL 直接灌）

| 检查项 | 怎么测 | 通过标准 |
|---|---|---|
| 波特率 | **115200** 发 `t0.txt="hi"` + `FF FF FF` | 屏上出 `hi`（若不动再试 9600，确认到底是哪个） |
| 文本控件 | `t0.txt="红球体"` | 出中文（乱码 = 字库/编码问题） |
| 数据记录 | `data0.insert("1^红球体^1")` + `FF FF FF` | 表格新增一行 3 列 |
| 图片控件 | `p0.pic=91` + `FF FF FF` | 显示第 91 号图片（应为"红球体"） |
| 错误码 | 观察 USB-TTL 回包 | 能收到 `1C FF FF FF` 等错误码 → 屏在回应，线是通的 |

> 判据：**文字能动、表格/图片不动 = 控件或指令名问题**（不是接线）；**连文字都不动 = 先查波特率**。

## 3 合体时的分层排查顺序（为什么是这个顺序）

**屏 → 电脑模拟 K230 → 主控→K230 触发 → 真 K230 → 电机/传送带 → 整机**

- **先屏**：纯单向输出，最容易独立验证，且能立刻确定 115200 到底通不通
- **再电脑模拟 K230**：电脑串口助手向 Serial2 灌 `Re,37,0.87`，排除 K230 侧不确定性，直接验证主控解析与分选动作
- **再主控→K230**：USB-TTL 并到 Serial2 TX 监听，确认 `image` 发得出去
- **再真 K230**：此时只剩视觉侧变量
- **最后执行机构**：它们会**掩盖**通信问题（皮带一转，你以为正常，其实是没收到结果）

> 每步只改一个变量。很多"整机不工作"最后发现是**两个人同时改了东西**——这就是为什么接口要先冻结。
